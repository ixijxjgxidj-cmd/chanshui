# T1 贪心匹配敏感性审计

日期：2026-08-11  
性质：规则/评分器审计，不是候选模型提分轮，不计作需要 15 篇新论文矩阵的完整研究轮。  
审计实现提交：`2c3d4d01f8b3306754103c3b30c107099e881f12`（`4bf7d51` 为本地最小验证版本；本记录以服务器复核为准）

## 目标与失败现象

官方材料只给出 P/S 单次到时误差的计分函数，没有说明同一文件内多个同相位预测与真值如何配对。项目评分器把所有容差内候选边按绝对残差排序后贪心认领；这在稀疏事件上通常合理，但不是严格全局最优，可能在密集多事件文件中改变到时总分甚至候选排序。

本审计只回答一个可证伪问题：当前冻结七成员预测在三套历史 T1 包上，是否因为贪心近似而得到与精确匹配不同的官方时差分？不改生产推理，不重新生成预测，也不借此选择任何模型参数。

## 预登记判断

- 若任一历史文件在任一精确目标下出现到时分或匹配数差异，则当前冻结评分存在匹配口径敏感性；必须报告逐包/逐相位差异，并评估候选排序是否翻转。
- 若 2,699 个文件的 P/S 逐文件到时分与匹配数全部相同，则关闭“当前历史基线受贪心近似影响”的风险，但不把结果外推为官方未来密集分布或贪心普遍最优。
- 审计器必须通过一个贪心确实次优的合成反例，否则“全相同”可能只是比较器实现退化。

## 实现

`scripts/audit_t1_matching_sensitivity.py` 保留生产评分器完全不变，使用 SciPy Hungarian assignment 独立实现两个目标：

1. `max_time_score`：直接最大化官方分段线性 P/S 时差分总和；
2. `max_cardinality_min_residual`：每条合法边加入足以形成严格字典序的基数常量，先最大化容差内匹配数，再最小化总绝对残差。

矩阵加入独立 dummy 行列，非法或零分边不会被强制配对。数量罚只依赖预测/真值总数，与匹配方式无关，因此本审计只比较到时分、匹配数和逐文件差异。

运行命令：

```text
python scripts/audit_t1_matching_sensitivity.py \
  --case round1=<第1轮答案包>::outputs/port_verify/r1_g7.an \
  --case round2=<第2轮答案包>::outputs/port_verify/r2_g7.an \
  --case final08=<08答案包>::outputs/port_verify/f08_g7.an \
  --output outputs/frozen_baseline/t1_matching_sensitivity_20260811.json
```

输出位于 ignored `outputs/`，不提交答案或逐文件敏感产物。本地最小复核 JSON SHA-256 为 `3b0e4c6b86a97c8f019d7543813131a35bcc265ac6206742204c495a7e4a98ba`；服务器同一实现、同一六份最小文本材料重跑的 JSON SHA-256 为 `1bfb06068fbf88847f3f446a9992f7d15ddfd43a7cbc66afb64f1244895fed36`。两份输出只因生成时间字段不同，结构与指标一致。

## 结论

当前三套历史 T1 冻结分数对贪心/精确匹配选择不敏感，保留贪心默认值以维持历史逐位连续性。该结论不是“贪心正确复刻官方”，也不证明未来密集记录无风险；合成反例已明确否证这种泛化。新密集包或官方书面匹配规则出现时，必须用同一审计入口重跑，并在存在实质差异时把精确多口径结果加入候选准入报告。
