## 当前成绩证据等级

`experiments/t1_g7_release_20260811.json` 记录的 T1 历史均分为：第 1 轮 `1.786294`、第 2 轮 `1.810140`、08 `2.010084`。对应预测文件有 SHA-256，可用于复现身份核对。

这些值目前是“带哈希的历史结果”，尚不是新冻结评估输出，原因如下：

- 历史包长期参与阈值、成员和后处理选择，存在显著调参泄漏风险。
- 当前默认计分使用 `merged_file_floor0`，但官方材料未唯一确定 5% 数量罚的聚合方式。
- release manifest 过去未记录第 1 轮和 08 包哈希；本文件已补齐事实，但仍需统一脚本重算。
- `geofon_m3` 的精确训练命令和数据池组成缺失。
- `geofon_m1` 没有真正独立留出集，使用三个历史分布做外部选择。

因此，所有新候选必须在同一冻结脚本下同时报告四种数量罚口径，并将历史包视为“回归/稳定性集”，而不是新的盲测集。

## 已确认的实现风险

### 1. T2/T3 短窗曾被 T1 下限误删（已修复，待发布）

统一摄入器原先对所有任务拒绝 `<5s` 波形。第 1 轮官方 T3 实际有 6 个 1.5–3.5 秒的合法第 5 类样本；生产 SeismicXM 离线对六条均分类正确，但旧 API 在模型前返回空表。当前工作树已将 5 秒下限保留给 T1/依赖 picks 的模型，对 `needs_picks=False` 的 T2/T3 固定窗模型允许短窗。完整测试、提交和服务器发布完成前，生产服务器仍是旧行为。

### 2. 缺口屏蔽未接通

`mseed_reader.py` 会检测分量缺口、用 0 填充并写入 `Waveform.gaps`，且注释明确说缺口内拾取必须否决；当前 `picker.py` 未使用 `Waveform.gaps`。这可能在零填充边缘或区间内制造假拾取。先量化历史包缺口率及当前预测命中情况，再决定是否上线屏蔽规则。

历史三包完整波形画像显示 T1 gap 文件为 0，因此这个不一致当前是未来鲁棒性问题，不是现有历史分数的直接增益来源。

### 3. 数量罚口径不确定

代码实现四种读法：`merged_file_floor0`、`per_phase_floor0`、`merged_exam`、`per_phase_exam`。现有 PPT 只给出“误差 5% 内不扣，每超一个扣 0.5”，未说明按文件/全卷、P/S 合并/分开。默认值只是历史兼容，不是已证明的官方真值。

### 4. 匹配算法是贪心近似

当前匹配将所有允许候选按残差排序后贪心认领，不是严格的全局最小总误差算法。官方匹配算法未公开。稀疏事件通常无差异，但密集多事件记录需做敏感性验证。

### 5. 训练谱系不完整

`geofon_m3` 缺精确训练配方；`geofon_m1` 无真实留出。它们可作为已冻结发布资产继续使用，但在补齐谱系前不能宣称完全可重训。
